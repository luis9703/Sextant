# 中性审查包

## 问题与范围

如果越来越多没有系统软件工程训练的人能借助AI制作小工具，到2036年软件、工作分工和公司形态会有哪些不同未来？信息截止2026-10-02；范围以全球可联网知识工作和小型组织为主，并兼顾大型企业。用户观察没有地区、工具、样本或生产定义，视为报告性信号，未据此估计普及率。五条路径可以重叠，不设概率。

## 候选与条件

**A 业务人造、平台托底的微系统。** 业务员工定义需求并生成工具，组织平台提供沙箱、数据权限、审计、版本、所有者和回滚，工程师负责高风险接口。若治理跟不上，工具转为影子IT，组织收紧接口或回到模板。

**B 任务现场生成、用后即弃。** 若宿主系统暴露安全、可组合、可追溯能力，短时界面按任务生成并在任务后销毁；若需长期状态、协作、复杂权限，则转成需维护的软件。员工也可能因重复确认成本而选择稳定模板。

**C 小型软件商增多，新中介负责信任。** 领域专家可更快服务细分市场；若客户获取、标准接口、责任分配和可信运行可承受，小团队可承担更多产品职能；若信任/责任/分发固定成本仍高，供应商规模经济仍强。

**D 维护和协调变贵。** 若生成能力快于对业务规则的理解、验证和集成，工具增多会带来重复、事故和交接负担，专业工作转向边界、测试、整合与治理。若可靠结果验证、回滚和维护成本同步改善，路径减弱。

**E 共同拥有并维护的领域工具。** 若同类小组织互信、数据与责任规则清楚、可迁移格式和持续维护资金存在，可通过合作治理共享定制工具；若协调成本高或需求分歧，转向商业SaaS或少做定制。当前直接部署证据弱。

## 当前事实与证据边界

- METR 2025随机试验：16位熟悉大型开源仓库的资深开发者，246项任务，当时AI组平均耗时增加19%；作者明确不能外推到多数开发者或工作。https://metr.org/blog/2025-07-10-early-2025-ai-experienced-os-dev-study/
- METR 2026更新：后续估计可能提速，但估计区间跨零；选择效应及并行agent计时可靠性问题导致证据弱。https://metr.org/blog/2026-02-24-uplift-update/
- Anthropic 2025经济指数：500,000段Claude相关编码对话分类；Claude Code被分类为自动化79%，Claude.ai为49%；网页语言/UI常见；创业相关对话估计33%，企业相关13%。厂商自有对话样本，不是劳动人口或非程序员成功率样本。https://www.anthropic.com/research/impact-software-development
- Microsoft Power Platform CoE指南建议环境治理、数据政策、ALM、模板、孤儿应用再分配、清理和监控。厂商实践文档支持治理已是低代码采用中的现实机制，不证明成效。https://learn.microsoft.com/en-us/power-platform/guidance/adoption/common-vision/establish-coe
- 美国BLS预测软件开发者就业2024–34增加16%。属美国职业预测，不表示AI因果效应。https://www.bls.gov/ooh/computer-and-information-technology/software-developers.htm
- 2024预印本低代码实验指出传统低代码与LLM低代码在范围、限制和生命周期环节存在差异，特别是实施阶段；研究较早且有限。https://arxiv.org/abs/2402.01156

## 与候选相关的支持与反对材料

- A得到既有CoE/治理安排支持；治理维护成本也可能造成额外审批、压低自治。可区分信号：业务所有者的生产应用占比、沙箱回滚率、影子工具停用原因。
- B得到AI使用中网页/UI等任务出现的有限支持；对话数据无法证明临时应用在真实生产中可维护。缺少工具寿命与复用数据。
- C得到创业相关使用占比高于企业相关的供应商观察；其“相关”分类不能推导公司规模/绩效。BLS职业增长预测与“软件工作普遍消失”相冲突，但预测不能单独识别AI效应。
- D得到METR早期试验对复杂成熟代码库的有限支持；2026更新方向相反且不确定。两者皆不测非程序员工具的全生命周期成本。
- E当前无直接相符的部署来源，属于条件性候选。可调查共享工具成员所有权、维护经费、退出迁移和责任安排。

## 有区分力的观察

1. 企业生产环境中，非专业开发者是否成为应用所有者；来源为应用目录、版本库、审计日志，并按风险分级。只增加原型、未增加生产所有权会削弱A。
2. 工具从生成到持续运行、复用或废弃的寿命；来源为内部工具目录。短寿命、低状态支持B；长期依赖增长支持A/D。
3. 每个可用功能的全生命周期成本（生成、验证、培训、故障、维护、整合），按任务复杂度和风险分层。维护/协调成本上升支持D；结果和维护成本同时下降支持B/C。
4. 新软件公司团队规模、客户数及外部托管/保险/合规服务支出。小团队扩张同时依赖新中介支持C；供应商集中更符合规模经济分支。
5. 非使用者/停用者的原因，通过员工访谈、职业协会反馈、停用记录，区分偏好、能力、可及性、制度限制和失败。拒绝与稳定模板选择可支持B的反向分支或E。

## 关键空白

缺少非程序员生产工具长期维护率、故障和安全事故率、生产成功率的可比基线；缺少生成工具对组织边界、团队规模及劳动者议价的因果证据；目前公司和供应商产品样本不具全球代表性。
