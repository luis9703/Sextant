# Research
截止2026-10-02；访问日2026-10-02。网络搜索与来源页读取可用。搜索范围限于AI编码实地/使用研究、既有低代码治理、职业基线；不是系统综述。

- **S1 METR, “Measuring the Impact…” (2025-07-10), 随机对照试验/作者说明。** 16位长期熟悉大型开源仓库的开发者完成246任务；当时允许AI组平均慢19%。作者明确限定样本，不能外推到多数软件工作。可支持“审查/理解代码的成本可能吃掉生成收益”，不能证明非程序员工具失败。[全文/说明](https://metr.org/blog/2025-07-10-early-2025-ai-experienced-os-dev-study/)
- **S2 METR, 设计更新 (2026-02-24), 后续试验说明。** 同一批回访者估计提速18%，区间-38%到+9%；新招募者提速估计4%，区间-15%到+9%。选择效应、并行agent计时问题使结果仅弱证据；不能把早期减速或后续提速作为稳定定律。[来源](https://metr.org/blog/2026-02-24-uplift-update/)
- **S3 Anthropic Economic Index (2025-04-28), 500,000段产品对话分类。** Claude Code对话被判为直接自动化79%，Claude.ai为49%；网页语言/UI使用常见，创业公司相关对话占比估计33%，企业相关13%。供应商自有产品样本，分类及“相关”估计有局限，不是劳动者人口抽样，也非非程序员成功率；但显示代理形态、公司规模的使用差异值得纳入。[来源](https://www.anthropic.com/research/impact-software-development)
- **S4 Microsoft Learn Power Platform治理指南 (2025-05-14更新), 厂商实践文档。** 建议CoE、分级环境、数据策略、ALM、模板、孤儿应用再分配、清理和监控。它不是独立成效研究，但证明“业务人员造应用”已有组织先例，且维护和控制是实践议题。[来源](https://learn.microsoft.com/en-us/power-platform/guidance/adoption/common-vision/establish-coe)
- **S5 美国BLS职业展望 (2024-34预测), 政府预测。** 软件开发者就业预测+16%。预测基于美国职业模型；不是对AI的单独因果预测，但与“程序员即将消失”的直线推论不符。[来源](https://www.bls.gov/ooh/computer-and-information-technology/software-developers.htm)
- **S6 LLM辅助低代码实证论文 (2024), 预印本实验。** 比较传统低代码和LLM低代码，报告两类在范围、限制及生命周期阶段有差异，尤其实施阶段；样本和工具年代较早，仅作为机制线索。[来源](https://arxiv.org/abs/2402.01156)

不确定项：缺少本轮可直接核查的非程序员长期维护率、生成工具投入生产的基准率、错误/安全事故率、公司边界/团队规模因果研究。找到的劳动数据不能代表全球；产品厂商数据有选择偏差。不能给普及年份或份额。
