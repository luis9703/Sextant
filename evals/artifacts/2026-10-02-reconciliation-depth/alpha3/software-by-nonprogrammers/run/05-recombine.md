# Recombine: second pass after research

1. **领域人造工具，转成受托管的“微系统”**（保留/细化初候选1、3）：既有低代码CoE说明治理并非遥远反弹，而是已存在机制；新条件是生成速度远超人工登记速度。团队可能出现由业务人提出、AI制作、平台守门人认证、工程师处理高影响边界的分层。新增后果：发布身份和责任链变成稀缺权限；若平台做不到自动来源追踪，工具可能退回个人草稿。
2. **临时界面走向“意图驱动、可丢弃工具”**（细化候选2）：LLM对话中用户可逐步构造小界面，但易生成不等于可持续。若数据/权限由宿主系统提供标准能力，工具像现场表单或宏，任务后可销毁；若每个工具持有状态、跨系统副作用，沉淀需求又把它推回产品生命周期。变化点是系统是否能让工具无状态、可回滚、可审计。
3. **软件供应从卖功能转为卖可信边界**（替换候选4的“公司必缩小”）：创业公司早用代理的厂商样本与“非程序员写小工具”兼容，但无法说明团队会普遍变小。更不同的因果路线是，公司围绕数据、责任和分发建立联盟：小团队能做更多功能，平台/保险/专业服务商因承担事故而扩张。
4. **省掉编码，反而增加需求与组织摩擦**（由S1/S2矛盾结果触发的失败分支）：若复杂任务验证仍贵，工具数量增多会增加审查、互操作和废弃成本。一线人员可用小工具推动改流程，也可能面对更多临时系统和额外值班。结果可能是“少写代码、更多整理/删工具”；拒绝/标准化成为有价值能力。
5. **小组织的窄域软件合作社**（保留候选5并展开）：若通用平台锁定或定制成本高，多个小组织共担维护，掌握共同数据模型和社区规则；这里不是公司简单消失，而是维护所有权从雇主/厂商移到成员网络。需条件：可互操作格式、稳定维护资金、明确责任。资料支持尚弱，作为条件性远景。

最近邻：citizen development/low-code CoE、软件即服务/内部影子IT、AI增强软件工程。此轮价值是把新生成能力与旧治理实践及短期AI测量不确定性连接；不是宣称新颖。
