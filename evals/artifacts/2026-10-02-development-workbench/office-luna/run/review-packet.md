# Neutral review packet: office suites, agents and HTML delivery

## Question, scope and cutoff

Question: after powerful AI models/tools and increasingly common HTML-based information sharing, will Office/WPS-like software still have market demand?

Scope: global productivity-suite ecosystem, with Microsoft Office and WPS as named examples; consider authoring, spreadsheet/presentation/document functions, collaboration, storage, identity, workflow, compatibility and records. China is a salient context but no China-only conclusion is requested. Distinguish need, use, willingness to pay, payer, vendor revenue and value capture. Cutoff: 2026-10-02. No forecast probabilities or fixed dates are assigned.

“Everyone is using HTML” is unverified and not treated as a population fact. HTML can be a delivery layer, interactive application surface or authored document; that does not automatically make it a calculation model, permission system or retained record.

## Conditional candidate pathways

### 1. Agent-created artifacts; suite as review/control surface
If AI agents become reliable at producing, changing and documenting complex documents, spreadsheets and presentations, users could spend less time in direct authoring and more on selecting, checking, reviewing and approving variants. The file remains a central object. The suite's paid value could persist through storage, identity, audit, compatibility and exception handling even if human editor time falls.

Conditions: reliable calculations/layout/citations; legible provenance; appropriate permissions and human override. Failure branch: errors are hard to inspect, so users restrict agents or return to direct editing. Alternative explanation for current vendor revenue growth: bundles, price/mix, security or collaboration services rather than document authoring.

### 2. HTML as a live view over a typed source; snapshots at institutional boundaries
If structured sources can safely produce permissioned, audience-specific web views, recipients may explore and discuss a shared object instead of receiving repeated decks. Source corrections could propagate, while versioned snapshots preserve what was approved. HTML serves discovery and presentation; an underlying model carries calculations and governance; Office/PDF remains an export or boundary format.

Conditions: semantic source, stable identity/permissions, export and offline fallback, accepted version history. Failure branch: mutable links, access gaps, conversion defects or records rules lead counterparties back to files.

### 3. Operational workflow becomes the source; documents become receipts
If agents can query business systems and preserve citations/replayable versions, teams could approve decisions in operational workflow tools and generate a brief or spreadsheet only when needed. The canonical record becomes event + inputs + rationale rather than a document. This is a distinct route from agents editing Office-native files.

Conditions: stable data contracts/APIs, accountability for recommendations, source snapshots and accepted workflow audit. Failure branch: fragmented data or a need for narrative persuasion keeps Office documents as boundary objects.

### 4. Compatibility/offline/institutional memory keeps files in circulation
If work crosses organizations, software access remains heterogeneous, archival obligations persist or offline/local editing matters, Office-compatible artifacts remain a common exchange and preservation layer. AI may increase file complexity and the need for repair, conversion and fidelity checking. Demand can migrate toward adapters, export, preservation and governance.

Conditions: continuing heterogeneity, native features or institutional attachment to portable artifacts. Failure branch: interoperability and provenance improve enough for institutions to accept live web-native records.

These branches can coexist across tasks and organizations.

## Developed episode and actor contrast

Temporary assumptions for the episode: one recurring internal reporting workflow has structured data and calculation semantics; an agent creates linked HTML views with role-based access, citations and history; the organization accepts a signed/versioned decision receipt.

An analyst checks an agent-prepared monthly performance explanation, corrects a source mismatch, and publishes a link. A regional manager filters it and asks a question anchored to a metric. One source correction propagates to all permitted views. On the next cycle, the team compares definitions and changes instead of rebuilding slides; the meeting shifts toward the decision and its assumptions. Repeated sharing moves scarcity from slide production to measure definition, permission, lineage and preservation. An access error or silent change can trigger a demand for an immutable snapshot. Failure to prove what was reviewed can return the team to Office/PDF exports, local replicas or static reports.

Bridge back: begin with a structured internal report; move templates to data-backed views; add semantic definitions and versions; introduce role-specific access; only after audit acceptance stop treating a deck as canonical. Reverse conditions include unreliable connectivity, cross-tenant access failures, uncheckable calculations, records rules requiring frozen files and errors in generated explanations.

For the same monthly decision:
- An internal team with stable shared data may prefer a live view if corrections propagate and definitions are inspectable; external recipients or audit snapshots may flip it to an Office/PDF export.
- A regulated counterparty may prefer a signed/versioned file if future inspection must survive access/policy changes; shared governed identity and accepted preservation can flip it toward live views.
- A small independent operator may use HTML/platform pages for audience reach and low-friction sharing; client editability, advanced calculations, archive needs or loss of platform access can make a suite/file worth paying for. Need/use can exist without high willingness to pay; an employer, client, platform or suite vendor may capture value separately.

## Current evidence and qualifications

1. Microsoft's FY2026 Form 10-K says Microsoft 365 Commercial cloud revenue grew 17%, seats grew 6%, Consumer cloud revenue grew 28%, and subscribers grew 7%. Commercial revenue bundles Microsoft 365, Enterprise Mobility + Security, Windows commercial cloud, Power BI, Exchange, SharePoint, Teams, security/compliance and Copilot. These are current results, not a causal test of AI and not Office-editor-only demand.
   Source: [Microsoft FY2026 Form 10-K](https://www.sec.gov/Archives/edgar/data/789019/000119312526323660/msft-20260630.htm), FY2026 vs FY2025, published 2026.
2. Kingsoft's 2025 annual report says office software/services revenue grew 16% to RMB 5,928.7m. Management attributes WPS individual growth partly to paying subscribers, broader scenarios and WPS AI upgrades, WPS 365 growth partly to document/AI/collaboration integration and enterprise expansion, and software growth partly to government/enterprise orders. Management attribution and broader segment mean this does not isolate AI causation or standalone editor demand.
   Source: [Kingsoft 2025 annual report](https://ir.kingsoft.com/static-files/999c2fb6-9739-4c00-a3d7-ec00dc5430b6), 2025 fiscal year, published 2026.
3. W3C calls HTML the Web's core markup language and describes web standards as supporting rich interactive experiences across devices. This supports HTML as a capable presentation/application layer, not “everyone uses HTML” or replacement of Office work.
   Sources: [W3C HTML](https://www.w3.org/TR/html/all/); [W3C Web Standards](https://www.w3.org/standards/).
4. ECMA-376 defines Office Open XML vocabularies and document representation/packaging. Microsoft's coauthoring documentation lists supported Office types and lists HTML/HTM as local-only for that described workflow. This illustrates current format/application distinctions and limits; those are not hard limits on future designs.
   Sources: [Ecma ECMA-376](https://ecma-international.org/publications-and-standards/standards/ecma-376/); [Microsoft supported file types for coauthoring](https://learn.microsoft.com/en-us/microsoft-365/cloud-storage-partner-program/plus/extensions).
5. Google documents editing Office files in Docs/Sheets/Slides and saving changes to original Office format, with conversion options and compatibility warnings. Google also documents offline editing subject to browser, extension, storage and sync conditions. This supports coexistence and hybrid delivery, not universal fidelity or offline parity.
   Sources: [Google Office file workflow](https://support.google.com/docs/answer/9406611?hl=en-419); [Google offline workflow](https://support.google.com/docs/answer/6388102?hl=en-NZ).
6. Microsoft describes agents that create Word/Excel/PowerPoint artifacts, with paid-license/admin/model conditions and tenant storage. Product documentation establishes current positioning and feature description, not quality, adoption or user willingness to pay.
   Source: [Microsoft Word/Excel/PowerPoint Agents](https://learn.microsoft.com/copilot/microsoft-365/wordexcelppt-agents).
7. Microsoft documents audit, retention, eDiscovery and immutable-data capabilities within Microsoft 365. This shows governance as a current product area; it does not establish enduring customer preference for an incumbent provider.
   Sources: [Audit log collection](https://learn.microsoft.com/en-us/compliance/assurance/assurance-microsoft-365-audit-log-collection); [Data immutability](https://learn.microsoft.com/en-us/compliance/assurance/assurance-data-immutability).

## Unknowns and observations

Not located: a credible global denominator for HTML as information-sharing method; product-level Office/WPS task shares; willingness to pay by actor; measured causal AI effect; comparative conversion-error rates; counts of workflows with an authoritative file vs live web object vs workflow event.

Potential discriminators:
- Separate editor minutes from suite seats/revenue and from identity, storage, security, compliance and AI usage; bundle/pricing changes are competing explanations.
- In sampled recurring workflows, identify which object actually governs a decision: file hash, live-object version or workflow event. Browser views alone do not identify canonicality.
- Measure Office/PDF round-trips, offline work, conversion defects and archival retrieval by workflow and reason.
- In production tasks, measure accepted versus materially corrected agent edits, error severity and review time; creation volume can mean value or costly rework.
- Observe whether HTML audience views lead to less retranscription and fewer attachments, or simply add another presentation channel.
- Distinguish new activity enabled by cheap generation from unwanted report volume and nonconsumption.
