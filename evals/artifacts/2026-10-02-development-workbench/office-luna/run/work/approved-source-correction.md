# Evolution follow-up: one source correction before and after approval

Temporary assumptions: one typed model powers live audience views; calculation history is preserved; each approval locks an evidence snapshot and records recipients; the team can mark decisions for reapproval. These are conditions of the imagined workflow, not current evidence.

## Before approval

An analyst finds an incorrect source mapping while preparing a monthly resource recommendation. The live page changes before anyone approves; a visible correction note shows old and new values and the affected region. The manager delays approval until the data owner confirms the mapping. Because no action has been taken, the corrected live source prevents copying the old figure into multiple decks. On the next cycle, the analyst begins checking field lineage earlier and asks the data owner to certify the feed before publishing. Fewer copies are made, but the data definition and change record now carry more organizational weight.

## After approval

The same mapping error is discovered after the manager approved and operations executed a capped transfer. The current view updates with the corrected source, while the receipt still shows the exact old evidence and recommendation that informed the action. The system identifies which decisions used the mapping and marks still-reversible actions as needing review. A team lead accepts the corrected conclusion for one region, a second requests a new decision, and a third exports the receipt with the correction log for audit. Recipients do not all make the same choice because the action's reversibility and impact differ.

Repeated use produces a rule: corrections that affect an unexecuted recommendation update it; corrections that affect an executed action trigger an impact notice and accountable human choice. People stop treating “latest page” as the whole truth. They want both present accuracy and past-state replay. The workflow expands from HTML display into change-impact analysis and reapproval; the living source does not eliminate snapshots but changes when and why they are produced.

## Failure branch and contrast to current candidate

If the mapping cannot be traced, a correction silently overwrites the previous value, or stakeholders cannot tell who approved which version, managers distrust the live source. They demand local copies and attach email context to a workbook, creating parallel records. A different response is to freeze all source updates until a monthly review, sacrificing timeliness for stability. Either may make a static document meeting more useful.

This adds a temporal governance mechanism to the existing “HTML lens over structured source” candidate: correction timing relative to approval changes propagation and action, and leads to a new routine for impact notices. It is not a new technology or a new market fact. Whether organizations will adopt such a rule is unknown.
