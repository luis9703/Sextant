# 避免流程误导和卡住想象的小范围修订

日期：2026-10-05。版本：0.2.0-alpha.8。范围由用户明确收窄到三个执行问题，保持顺序、文件完整性和登记异议字面位置检查的边界。

| 问题 | 实现行为 | 检查范围 |
| --- | --- | --- |
| plan_work误带尚未开始阶段的综合合同 | 只给缺失工作种类和可解析的development.md；正常工作、阶段仍有各自合同 | 不规定候选内容或发散数量 |
| 早期路径partial永久阻塞 | 必需工作与所有待办完成，且当前综合已有匹配这些材料的审查后更新或确认时，历史partial进入superseded_partial_phases；原回执和文件保留 | 其他partial、未完成工作或过时检查点仍不能完成；不判定综合质量 |
| 省略编号的摘录继承上一条处置 | 有登记异议时，摘录显式带已登记编号；未知编号、漏编号、用F1替代F2位置均拒绝 | 无登记异议仍可引用保留主张；短摘录合法，字面匹配不证明修复充分 |

WorkBuddy说明将审查限制写入实际审查材料、回执及报告状态，资料缺口写入相关foothold/research材料。九阶段运行不为此新增exploration.md。产品架构文档开头说明当前已有可安装原型，保留早期设计更新。

## 实际定向检查

在原实现上新增用例，观察到plan_work错误附带路径/对账合同，以及F2处置后的无编号单字摘录被接受。修订后执行合同模块18项测试通过，包含在全套84项回归中。

恢复用例分别走新版本和原文确认两条路线：先记录路径partial、完成审查，再补齐演化、比较与一个后续问题；待办存在或检查点过时时仍是partial，更新或确认当前综合后可完成九阶段，verify为pass，next为recorded_complete，历史回执和原文件不变。

编号用例拒绝无编号、未登记编号及F1代替F2的关联；显式编号和位置正确的单字摘录仍被接受。这验证记账关系，不验证语义充分性。新增保留用例确认：登记材料异议后，可以解释保留理由、确认原综合并完成交付，原综合不变。回归继续覆盖未决、不采用，以及无登记异议时的中文无编号主张摘录。

实际完成的检查：

- `python3 -B scripts/check_project.py`：0 errors，0 warnings。
- `python3 -B -m unittest discover -s tests -v`：84项通过。

本轮没有新增模型前向推演：修改针对已复现的执行行为，不改变想象操作。既有alpha.7前向案例及私有运行不重新评分。定向脚本测试不能证明想象改善、跨模型稳定性或预测能力。

## 保留的边界

没有自动抽取异议，没有要求每个问题必须修改，没有摘录长度门槛或语义评分，没有收紧adopt-existing，也没有把breadth_prompts变成完成清单。保留、未决和不采用仍是合法处置。条件未来可以携带未决交付，程序pass仍只表示当前执行记录满足结构约定。
