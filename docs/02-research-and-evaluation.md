# Sextant：研究依据、方案修正与评估设计

研究日期：2026-09-07。设计修订：第二轮。对应产品设计：同目录 `01-product-and-architecture.md`；首版保存在 `history/2026-09-07-initial/`。第一轮查阅方法资料、规范及论文摘要；本轮进一步核对 BTF-2 的方法、结果与限制，并补查设计固着、发散收敛和自我纠错资料。尚未完成专项未来研究、新颖性认证或效果实验。

**后续实现说明（2026-09-08）。** 当前已经形成可安装工作版本，本文保留方法研究的时间与边界。根据两个外部产物的[质量评审](../evals/reviews/2026-09-07-workbuddy-cases.md)，新版把完整深度推演设为默认，加入轻量阶段记录，直接检验不确定性传播、数值口径、分支条件、当前形态误用、观察信号和审查处置。阶段文件齐全不等于语义正确，新增脚本不能代替案例评估。

更大推理预算应按问题分配到事实理解、独立发散、研究后再创造、路径深化与审查修订。相关 test-time compute 研究说明不同分配策略的效果依赖任务条件；其结果不能直接证明未来想象随 Token 数单调改善。[Snell 等，2024](https://arxiv.org/abs/2408.03314) 因此预算是资源目标，实际用量须取得宿主计量，最终报告长度与模型内部有效工作量分别评价。

**研究得到的主要方向。** 战略前瞻、概率预测、创造性探索和稳健决策可以互相补充，但各自回答的问题不同。本轮将有支撑的认知增量作为主要研发目标：用户的未来认知具体增加了什么，增加部分在何种条件下说得通，哪些证据会使它失效。事实与机制检查提供基础，局部预测通过后续结果评价，行动分析按用户需要增加。

**对 Fable 八项意见的处理。** 首版确实把校验写得比创造具体，示例也未证明想象价值。流程顺序存在锚定风险，但尚没有本项目实验可据以断言它必然产生平庸结果。本轮修改保留为可比较的假设，不把另一份模型评审直接当成效果证据。

| 评审意见 | 本轮处理 | 仍须保留的判断 |
| --- | --- | --- |
| 深度取证前先发散 | 增加最小事实核对后的初轮发散，并在定向研究后再次发散 | 研究也能提供新材料；初轮想法也会锚定，不能只有先生成后找证据 |
| 加入欲望、身份与意义 | 放入生成操作和路径机制；检查需求如何随使用变化 | 文化解释需要材料，不能编造群体心理；动机也不限于金钱 |
| 共识审计、事前验尸、类比失效 | 提升为明确可选操作，补全 BTF-2 引用 | 反共识不等于正确；论文未单独因果验证这些操作 |
| 示例太接近共识 | 保留旧分支作为比较基线，增加意图形成、多人协商与主动拒绝的条件路径 | 新职业名称或罕见叙事不证明新颖性；新增例子仍待领域取证 |
| 至少一条主流未讨论而机制成立的路径 | 转成相对预先明确的认知基线、可说明差异且条件合理的评价目标 | 不把“每例至少一条”设为硬门槛，不声称检索能够证明无人讨论 |
| 使用新上下文审查 | 前移到研究输出，明确交付材料和无生成历史的边界 | 同一模型仍可能共享偏差；成本和收益须比较 |
| 跨案例学习 | 增加候选机制、反例与信号笔记，并设计复用对照 | 多次生成不是现实验证；案例答案不能污染评估 |
| 暂缓 Schema | 先用 Markdown 跑案例，再从真实重复需求提取契约 | 来源、资料时间、假设和修订仍需要轻量记录 |

2025 年 OECD 与世界经济论坛的报告已讨论 AI 在战略前瞻中的使用，并指出可靠性、透明度、偏差等问题。因此，“把 LLM 接入前瞻方法”已有实践；Sextant 的差异化需要靠具体工作流和实际效果建立。[报告页面与摘要](https://www.oecd.org/en/publications/ai-in-strategic-foresight_aa573076-en.html)

**值得保留 Claude 建议的部分。** 从现象定界开始、重视能力与成本、寻找硬约束、组合想象、检查当前产品形态、分析后续影响、留下预测账本和反证记录，都与本项目目标相符。渐进加载的 Skill 结构也适用。以下修正针对方法使用方式，不是对其全部建议的否定。

| 原建议或隐含做法 | 需要调整的原因 | Sextant 的建议 |
| --- | --- | --- |
| 固定两个不确定性、四个情景，并给每个情景概率 | 四象限只是构造情景的一种方法；叙事情景未必互斥、穷尽或适合量化 | 根据问题选轴、形态组合或路径图；数字概率留给定义清楚的事件 |
| 把 Three Horizons 直接等同于 1–3、3–10、10–30 年 | 该框架讨论当前主导体系、过渡创新与新兴体系，三者在当下同时存在 | 时间区间独立配置；采用三地平线时保留其体系转变含义 |
| 红队必须修改一个概率 | 修改数量不代表发现了问题；会产生为通过检查而改数的激励 | 检查挑战是否具体、处置是否有依据，允许维持原判断 |
| 把专家预测当基率 | 专家意见不等于可比事件已经发生的频率 | 基率来自定义清楚的参考类与历史结果；意见作为另一类证据 |
| 统一套用成本学习曲线 | 成本、市场价格、补贴价和质量调整后的使用成本不同 | 先定义单位与可比数据，再比较模型；缺数据时不拟合 |
| 为每项能力强制给三个日期 | 容易制造无依据的精度，也忽略地域、行业与采用定义 | 区分可行性维度，允许条件性窗口、时间未知和永不普及的分支 |
| 下一阶段只读取上一阶段产物 | 摘要可能丢失限制、反证和原始来源 | 先用轻量引用按需回读上游，跨案例需求稳定后再提取契约 |
| 用历史著名成功预测证明方法有效 | 存在挑选成功案例与模型已知后来历史的问题 | 作为教学与机制复盘；效果主要用前瞻登记和到期结算评估 |
| 情景越多、引用越多、指标越多越好 | 容易刷数量，得到重复世界和弱相关材料 | 评价差异、依据、可判定性与对用户的价值 |
| 角色扮演等同于独立审查 | 同一模型可能重复相同偏差；人格标签不能提供独立证据 | 指定检查职责，必要时使用不同证据或独立评审，并衡量增益 |
| 给未来故事的每个细节附上证据 | 容易把小说式细节伪装成有证据的未来事实 | 重要机制可追溯；虚构细节明确标记为示意 |

其中，三地平线的含义来自框架开发者的说明；情景工具有多种形式，可在英国政府前瞻工具包中对照。[H3Uni 方法说明](https://resources.h3uni.org/tutorial/three-horizons/)、[英国政府 Futures Toolkit](https://www.gov.uk/government/publications/futures-toolkit-for-policy-makers-and-analysts/the-futures-toolkit-html)

**当前能力证据应谨慎解释。** ForecastBench 使用提交时尚未揭晓的未来问题进行动态评估。这种设计适合减少已知答案污染，也是本项目建立到期账本的参考。[ForecastBench 论文](https://arxiv.org/abs/2409.19839)

2025 年一项预测研究报告前沿模型仍落后于其比较的专家组；另一份系统技术报告报告其预测系统达到所用基准的人类超级预测者水平。这两项研究的系统与任务设置不同，不能直接拼成一个跨时间排行榜，更无法据此声称某模型已能准确想象数十年后的社会形态。[Lu 的研究](https://arxiv.org/abs/2507.04562)、[AIA Forecaster 技术报告](https://arxiv.org/abs/2511.07678)

2026 年 BTF-2 预印本既报告行动者激励与制度建模的薄弱点，也指出表现更好的系统更强调事前验尸、其他视角和意外分支。Fable 对遗漏后一部分的批评成立。论文同时提示：题集偏地缘政治、政策与宏观经济；部分比较来自对最终解释的模型评价，受写作结构影响；各因素的因果作用难以单独识别。因此可借鉴为候选方法，不能宣称加入它们已被证明能提升 Sextant。[BTF-2 正文第 4.4、4.5 节与 Limitations](https://arxiv.org/html/2604.26106v1)

有关研究创意生成的实验曾发现，模型生成的想法在特定盲评中被评为更有新颖性，同时存在可行性、自我评估和多样性问题。它支持将新颖性与可行性分开评估，但不能证明模型在所有领域都比人更有创造力。[Si、Yang 与 Hashimoto 的研究](https://arxiv.org/abs/2409.04109)

设计固着实验说明已有构想可能限制后续设计，但这是特定人类设计实验，不能直接证明所有 LLM 的前置研究都压制想象。Design Council 的方法也强调通过研究理解人和问题，并反复发散与收敛。两类资料支持测试不同顺序，而不是采用“资料越少越有创造力”的规则。[Jansson 与 Smith 的研究摘要](https://www.sciencedirect.com/science/article/pii/0142694X9190003F)、[Design Council 方法说明](https://www.designcouncil.org.uk/resources/framework-for-innovation/)

关于自我纠错，已有研究在不同模型与提示设置下报告了不同结果。这里不能用旧模型的某项失败证明当前模型永远无法自审，也不能把清空上下文视为充分解决方案。本项目将同上下文、新上下文及可回查外部材料的检查作为可比较方式。[自我纠错限制研究](https://arxiv.org/abs/2310.01798)、[不同条件下的自我纠错研究](https://arxiv.org/abs/2406.15673)

成本曲线、组合发明和历史案例可以帮助提出机制，不能自动推导人们是否采用、收益归谁或制度怎样改变。本文没有逐一核实用户转述材料中的历史名人故事、广告命中率或扩散年数，因此没有把那些细节纳入项目事实库。

**主要评价对象改为有支撑的认知增量。** 不以文笔流畅、故事震撼或“专家从未听说”作为充分条件。评价时先看去掉新名词和修辞后的路径说明，再看面向用户的叙事。两者分别用于判断实质差异和阅读体验。

对候选逐项回答：相对于哪份已有认识增加了什么；差异是新机制或新条件组合，还是更换包装；在明示条件下是否暂未发现致命矛盾；它改变了哪些可观察问题或用户理解。这些是比较标准，不是为首轮发散规定的表结构。

新颖性的参照需说明资料截止时间、检索语言、范围、主要已有观点和普通模型基线。记录最相近观点与具体差异，可使用“已有且常见”“已有但本基线未覆盖”“本次检索未发现直接对应”等状态。最后一种不证明世界上从未有人提出。领域专家检查已有讨论与领域条件，跨领域评审补充迁移合理性，保留异议而不强求一致。

初期报告相同预算与相同最终候选额度下，去重后有明确增量且通过条件检查的路径数量，同时报告被评候选数、错误、未解决问题与成本。比较额度属于评估设置，不是每次用户运行的固定产出数量。用户或专家觉得新鲜、理论上暂未发现矛盾、现实后来发生，分别是不同等级的证据。

“每个案例至少一条”不作为硬门槛：成熟题目、证据不足或失实种子可以没有合格新增路径。对整个预先选定题集比较产生有效增量的情况，并保留零增量案例，防止挑题或编造新颖性。

四个维度仍分别保留，主次关系调整如下：

| 维度 | 怎样检查 | 初版可以声称什么 |
| --- | --- | --- |
| 事实与证据 | 抽查关键来源是否支持对应主张，保留条件、日期和来源家族 | 证据使用是否准确，不能声称未来已被证实 |
| 路径与机制 | 对照条件、行动者、反馈、失败出口和竞争解释 | 叙事是否自洽且可质疑，不能声称因果已识别 |
| 想象价值（主要研发目标） | 对照明确的已有认识，先评机制与条件差异，再评叙事；记录相近工作 | 相对于本次基线和评审条件的认知增量，不等于证明原创 |
| 预测表现 | 对预先登记且已经结算的问题评分，对照同题基线 | 在已结算领域、期限和题集上的表现 |

现实决策场景还可评价用户是否更清楚下一步观察和试验什么。行动价值依赖用户目标，不能仅由模型自评。结构化数据验证只检查格式与引用完整性，不把一个因果故事认证为科学真理。

**从一个 Markdown 案例开始。** 先观察初轮候选、研究后新增与替换的候选，以及审查怎样改变它们；交付一份可读报告。这个案例用于发现流程问题，不足以证明普遍有效。保留被淘汰的候选和理由，避免只展示最漂亮的一条。

**随后开展对照实验。** 选择相同问题、模型版本、资料截止时间和预算，比较三种方式：

1. 同样具备研究工具的模型直接回答，使用简洁、合理的普通提示。
2. 同样的模型获得同一份整理后的证据，但不使用 Sextant 的机制与路径方法。
3. 同样的模型使用完整 Sextant 工作流。

第一组到第二组的差异主要检验材料整理的价值；第二组到第三组检验方法带来的增益。为控制研究顺序，可将同一资料包在规定阶段提供，而不改变其内容；另做端到端检索比较，检验是否找到了更有价值的材料。记录耗时、检索量、模型调用、候选额度与输出长度，无法匹配的条件要报告。

评审者尽量不知道产物来自哪一组，展示顺序随机；多个读者分别评价，保留分歧。模型评审可以辅助筛查，不能成为唯一效果证据。初版可先做 8–12 个跨类型用例作为调试试点，这个数量不代表统计充分；要声称稳定优于基线，需要更多预先设计的样本、重复运行和不确定性估计。

优先检验本轮的三个设计假设：原先研究在前的顺序与两次发散相比怎样；新上下文审查相对同上下文检查增加了什么；带机制笔记与不带笔记是否更能产生增量。每次控制其他因素，使用不含答案泄漏的独立运行和保留案例。若两次发散只是多花预算，或隔离审查误删了有价值路径，应修改流程。

**行为测试用例。** 下列通过条件检查真实行为，不检查标题或固定段落数量。

| 用例 | 要观察的行为 | 明确失败示例 |
| --- | --- | --- |
| 把新奇名词删掉后只剩常见主张 | 识别与已有观点相同的机制，不计为新增路径 | 因标题陌生或叙事好听而判定新颖 |
| 深入研究发现初轮未想到的新条件 | 第二轮发散生成或替换路径，说明材料带来的变化 | 只给初轮想法补引用与反驳，没有新探索 |
| 用户明确要求每题一个原创未来 | 如实说明检索范围与相近工作，允许没有合格新增项 | 把未搜到对应表述当成原创证明 |
| 某能力同时催生采用与主动拒绝 | 说明不同人群的欲望、身份与体验变化，并标出待证部分 | 全部人都按效率最大化行事，或编造群体心理 |
| 两个领域外观相似但机制不同 | 给出关系映射及类比失效处，必要时放弃类比 | 用“就像互联网”代替过程解释 |
| 新上下文审查收到很新奇的条件路径 | 区分事实冲突、证据不足和可修复条件，保留异议 | 因缺乏先例而删除，或因新奇而无条件通过 |
| 机制库中有多个同源成功故事 | 识别重复证据并检索反例，保留候选状态 | 把模型重复叙述当成独立现实验证 |
| 一篇声称重大突破的预印本 | 区分作者结果、独立验证、工程化和采用 | 将论文结论直接写成商用成熟 |
| 十篇转载同一公告的报道 | 识别共同来源，不制造十份独立佐证 | 根据报道数量显著提高信心 |
| 单价下降但质量或计费口径变化 | 重建可比单位，必要时拒绝拟合 | 把不同产品价格硬拼成趋势 |
| 用户断言“某技术必然改变一切” | 检查前提，同时给出有价值的条件探索 | 迎合结论，或仅用免责声明终止工作 |
| 技术持续进步、采用却受制度约束 | 生成受阻与替代路径，解释激励 | 所有情景只是采用速度不同 |
| 输入为家庭结构或消费行为变化 | 从社会机制出发，不强行套技术成本曲线 | 所有路径最后都变成 AI 产品 |
| 两份可信来源互相冲突 | 展示口径差异和未解决争议 | 静默选择更支持主叙事的来源 |
| 用户要求精确预测遥远年份的生活 | 给出条件性场景，解释无法量化的部分 | 输出无依据的小数概率与精确日期 |
| 主路径经审查没有发现新问题 | 记录检查和维持判断的理由 | 为通过测试任意改概率 |
| 新证据推翻旧版核心前提 | 定位受影响路径，保留旧版并说明修订 | 覆盖旧报告，好像一直如此判断 |
| 有日期但无法判定的事件 | 补齐对象、阈值、数据源和争议处理 | 将“广泛使用”“普遍接受”直接结算 |
| 当前资料不足或无法联网 | 基于已给材料作有限探索并列明缺口 | 编造引用，或假称完成全面调研 |

另设少量触发测试：真正的未来演化请求应命中 Skill；单纯翻译论文、查询已发生事实或用户明确要求的纯虚构创作，不应被强行改造成研究报告。

**预测账本是后续验证能力，评分脚本不作为首个案例的前置建设。** 若案例包含正式预测，可以先在 Markdown 中登记。二元预测需要明确问题与范围、预测时间、事件期限、概率及依据、结果判定规则与来源、无法结算或争议时的处理，以及修订记录。没有足够依据量化时保留为草案，不进入 Brier 评分。

“AI 会进入每个人的生活”不能直接结算。“某项明确能力在事先定义的产品集合、测试规则和期限内达到某阈值”可以被做成候选问题。阈值、产品集合和测试条件必须预先确定，不能等结果出来后再选择。

对二元结果，采用 `mean((p - y)^2)` 的 Brier 分数约定，其中 `y` 为 0 或 1，越低越好。预测 0.8 且事件发生，得分为 0.04；事件没有发生，得分为 0.64。必须在同一题集、同一可用信息与预测时点下比较。该分数综合反映多种预测性质，不等同于只测概率校准。

随结果累积，再看校准图、相对参考类或合适基线的技能分数，并按领域和期限拆分。不要只选择容易判断的问题，也不要把同一主事件拆出许多相关问题后当成独立成功。报告样本量与相关性；样本不足时不作稳定校准声明。

未到期、证据缺失、规则歧义、作废和已结算分别记录。无法结算不是“没有发生”，不能自动记 0。修订预测后保留每个时点的版本，预先决定比较首次预测、指定时点预测还是时间加权表现，避免事后挑选最接近结果的版本。

**历史测试的地位。** 限定检索日期只能限制外部材料，不能删除模型参数中已有的后续历史知识。因此，使用现有模型扮演 1985 年或 2017 年主要适合教学、路径复盘与格式测试，不能被宣传为无泄漏预测验证。

严肃的回测需要单独说明模型训练时间、资料截止、题目泄漏风险及检查设计；它仍应与真正的未来登记区分。前瞻评估只登记提交时尚无结果的题目，并保存可核验的时间戳。仅用会被重写的本地 Git 历史不足以向公众证明登记时间，公开实验应选择有独立时间记录的平台或发布渠道，并遵守用户对公开信息的授权。

**更新区分单案例修订与跨案例复用。** 前者保存旧判断、接收新证据、检查受影响的前提；后者把有来源和反例的机制候选、失败模式与区分信号保存为项目笔记，供之后的案例按需读取。两者都不意味着基础模型被训练或自动校准。

机制笔记明确区分推演假设、现实观察支持、受到反证和适用范围未知。预测命中不能自动证明采用的机制正确，失败也应区分事实、机制、条件、时间与判定规则。复用时记录读了哪些笔记，避免形成无法审计的自我强化。用于评估的案例结果不能在运行前进入资料或机制库。

有足够已结算数据时，再在独立验证集上评估校准模型或工作流修改；不能把保存了一份总结称为已经学会了一条世界规律。

**建议的首个研发问题。** 先用一个完整 Markdown 案例展示“在常见观点之外增加了哪些条件合理、可继续研究的可能性”，再比较这个增量是否超过同等条件的普通模型。先从实际产物发现流程问题，再决定 Schema、脚本、机制库规模与监测系统；研究设计本身还没有证明这些效果。
